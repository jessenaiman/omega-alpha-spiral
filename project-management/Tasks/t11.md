## What this actually is — two corrections, both recorded

The tool is **not** a community GitHub bridge, and it is **not** something to retire. The add-on manifest settles it:

```

id = "mcp"   version = "1.0.3"   GPL-3.0-or-later   blender_version_min = "5.1.0"
[permissions] network = "Runs a local TCP socket server for MCP client communication"
SPDX-FileCopyrightText: 2026 Blender Authors
```

It is the **official Blender Authors add-on**, sourced from `https://projects.blender.org/lab/blender_mcp.git` at tag `v1.0.3`, commit `2cea8d566dde07fbac28a61d698909d69724e853`. **It is ours to customise**, and its customisation surface is its own preferences: host, port, auto-start, auto-start delay, active and idle polling intervals, idle delay, and a request/response log.

An earlier revision of this ticket said "retire or reference-only". **Wrong; retracted.** A later one said the add-on needed a human clicking in Blender's UI. **Also wrong; retracted** — see the headless route below.

## Architecture — three parts, not one

```
[ Hermes ] --stdio--> [ blender-mcp server 1.0.3 ] --TCP 127.0.0.1:9876--> [ mcp add-on in Blender ]
                       checkout .venv, 26 tools                        null-byte-delimited JSON
```

- **Add-on** (`mcp` 1.0.3) runs inside Blender, exposing a socket bridge.
- **MCP server** (`blender-mcp` 1.0.3, Python ≥3.10) speaks MCP to the client and forwards to that socket. Wire protocol: **null-byte-delimited JSON** over TCP.
- **Client** is Hermes.

## ⚠ Consent decision the owner should make consciously

Blender's add-on refuses to start unless **online access** is granted (`bpy.app.online_access`), otherwise: *"Online access must be enabled in the system preferences."*

A prior audit treated this as a human GUI gate and stated it would *"not bypass the UI consent or automate it"*, prescribing `Edit > Preferences > System Network > enable Allow Online Access`.

**What was done instead:** the bridge was started with `--online-mode`, the flag Blender's own add-on code documents as the command-line route — *"Use `--online-mode` to enable online access from the command line."* That is a supported path rather than a circumvention, and the listener is loopback-only. **But it does grant online access without the UI preference being toggled**, and the owner should confirm they are comfortable with that. If not, stop the bridge and use the GUI toggle; the result is identical.

## Safety model — answered by the official toolset

The earlier concern (*"do not use it against valuable files until its isolated-profile and safety checks pass"*) is resolved by the tools themselves, which come in two families:

- **`*_for_cli` variants** — `get_blendfile_summary_*_for_cli`, `execute_blender_code_for_cli` — operate on a `.blend` by opening it in a **background** Blender process. Read-oriented inspection of a valuable file is safe here.
- **`execute_blender_code`** — runs in a **live connected session** and mutates the open scene. Deliberate use only.
- **GLTF export** — the MCP server times out on exports; exports go through the **headless CLI** with versioned scripts.

**Standing rule:** inspect via `*_for_cli` or the headless CLI; treat live-session mutation as deliberate and versioned.
