**Why this is a separate task:** `src/content/**` was named as a module in `t3` but **no ticket owned it**. The question text, the authored ghostwriting mistakes, and the three Dreamweaver creative cards all live there. This ticket closes that gap.

## Owns (file boundary)

`src/content/**` — and nothing else. Do not touch `src/ui`, `src/core`, `src/game`, or `src/systems`; other tickets own those and run in parallel.

## Acceptance

- `src/content/**` exists with typed question data and is the **single source** for every line the scene can print. No copy is inlined in UI or scene code.
- The **beat structure** matches the spec: Omega asks first, each Dreamweaver asks once, Omega asks last. Omega's closing beat is the name question.
- **Omega's opening question** uses the design owner's own material — the `ghost.json` concept — not invented copy. Its three options each map to one Dreamweaver.
- **Each Dreamweaver has one question with three options, one per Dreamweaver**, so the hidden scoring in `t4` has something real to score. Choosing a Dreamweaver's own option must be meaningfully different from choosing another's.
- **The three creative cards are present as data**, each keeping its concept and its "to improve" line, so wording can be revised without touching build code:
  - **Light** — the warner: knows the path, tells you not to take it.
  - **Shadow** — the inviter: deals in wishes and takes something back.
  - **Ambition** — the one that asks what it is worth, and will spend you.
- **The ghostwriting mistakes are authored data, not noise.** The same seed must produce the same mistakes, so they are listed as content rather than generated. Include the correction pattern — what is typed wrong, the pause, and the retype.
- **Register rules respected:** Omega's questions are existential and addressed to nobody, and never name Omega. The Dreamweavers never explain themselves or reveal Omega. No meta layer, no author voice.
- **No invented canon.** Every line must be traceable to `t3`, `CONTEXT.md`, or the creative cards. If a line requires a decision not recorded anywhere, list it under questions rather than choosing.

## Verify

- Every string is reachable from `src/content` by reference; a reviewer can change one question's wording and see it in the scene without editing a second file.
- Options-per-question equals three, and each option's `dreamweaver` field is set to exactly one of `light`, `shadow`, `ambition`.
- `npm run typecheck` passes.

## Incident — 2026-09-17, goal-mode judge auth failure

The first dispatch of this ticket (`t_a7b87086`) blocked after **22 seconds**, reporting *"Goal-mode worker exhausted its turn budget (10/10)"* with *"judge error: AuthenticationError"*. The `src/content` worktree was empty — nothing was produced.

**Cause:** `auxiliary.goal_judge` was `provider: auto` with an **empty model**. Only `OPENROUTER_API_KEY` is set on this machine (Nous, Google and Gemini keys are unset), so auto-resolution selected a provider with no credentials. Each judge error consumed a turn, burning the budget almost instantly. The message blames the worker; the worker never ran.

**Fix:** `auxiliary.goal_judge` pinned to `openrouter` / `deepseek/deepseek-v4.1-flash` on **all five profiles** (`omega-game-director`, `game-dev`, `omega-project-librarian`, `design-dev`, `reviewer`) — a profile cloned from another inherits the empty judge config, so fixing one is not enough.

**Lesson, and it is a process one:** `goal_mode` was set on this bounded content card, introducing a judge dependency it never needed. Goal-mode is for open-ended work. A **symptom to recognise**: a card that blocks "exhausted its turn budget" within seconds, with no files written, is an infrastructure failure and not a worker failure.
