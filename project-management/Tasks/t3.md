> **Scope of this spec, per the design owner (2026-09-17):** *the visual of the text and the playable scene.* The Dreamweaver dialogue is explicitly **not** being finalised here; each gets a creative card (see Further Notes) so the wording can be iterated without touching the scene.

## Problem Statement

The player's first minute does not exist. The repository boots a canvas and prints `GHOST TERMINAL · INITIALIZING`; there is no scene behind it. The only Scene 1 design that exists is an AI interpretation of the owner's writing, and it reads as a multiple-choice form on a black rectangle — a static throwback whose alignment is announced on screen. It does not look like a machine learning to build a world, and it does not feel like the opening of a story worth replaying.

The owner's problem, in their words: *"a completely made up rushed first scene that doesn't understand or reflect my story."*

## Solution

Scene 1 becomes a single continuous, input-driven descent. It opens on nothing — a bare blinking cursor on black, no frame, no border. Code begins to move. The first question ghostwrites itself, making mistakes, correcting them. The console pulls off the frame and becomes a 3D object while the background flickers with attempts to load more code.

Behind all of it sits a second layer that is **not built from Omega's code**: the vastness of the universe, carrying the moving lemniscate. The terminal **follows the lemniscate's path**, and the journey along it is the scene's spine. Where that path ends, the terminal becomes **the door** — and the door opens onto the final question.

The three Dreamweavers appear only as whatever Omega can currently render — a dot, then a line, then a box, then an icon — always inside what the code loop has added. They never glitch. They never show a face. Their identity is carried by **behaviour and motion**, not by shape, because shape is the one thing the ladder keeps changing.

By the end the terminal has popped out of the frame into 3D and is still typing.

## User Stories

1. As a player, I want the scene to start on true black with nothing but a blinking cursor, so that the first thing I see is an absence rather than an interface.
2. As a player, I want the cursor to be the only affordance at the start, so that I know the machine is waiting for something without being told.
3. As a player, I want code to begin moving on its own before anything is asked of me, so that I understand something is already running.
4. As a player, I want Omega's first question to ghostwrite itself with visible mistakes and corrections, so that I believe a struggling machine is typing rather than a script playing.
5. As a player, I want the pauses between typed characters to be long enough to feel like processing, so that the machine's slowness reads as effort rather than as lag.
6. As a player, I want the console to pull off the frame and become a 3D object, so that I feel the world acquire a dimension rather than switch scenes.
7. As a player, I want the background to flicker with failed attempts to load code, so that I can see the machine reaching for capability it does not have yet.
8. As a player, I want failed assets to be replaced by their own source — raw code or an error where a picture should be — so that the machine's failure is visible rather than hidden.
9. As a player, I want to see the vastness of the universe behind the machine, so that the machine reads as small and the story reads as large.
10. As a player, I want the lemniscate to move in that background, so that there is a shape I am following even when I do not yet know what it is.
11. As a player, I want the terminal to travel along the lemniscate's path, so that the journey has a direction and an eventual end.
12. As a player, I want the journey to arrive somewhere, so that the final question feels reached rather than presented.
13. As a player, I want the terminal itself to become the door at the path's end, so that the threshold is the machine rather than something bolted onto it.
14. As a player, I want the terminal to pop out of the frame into three dimensions and keep typing while it does, so that the last thing I see is a machine still trying.
15. As a player, I want sparks and effects to punctuate the journey, so that advancing feels like something is being generated.
16. As a player, I want those effects to show where the machine is reaching back from — earlier, cruder generations — so that progress is legible as recovery rather than as decoration.
17. As a player, I want a Dreamweaver to first appear as a dot, so that its arrival is the smallest possible event.
18. As a player, I want that Dreamweaver to become a line, then a box, then an icon as the loop advances, so that I can measure the machine's learning by what it can render.
19. As a player, I want the ladder to never regress, so that the scene's progress is trustworthy.
20. As a player, I want no Dreamweaver to ever glitch, so that they read as whole in a world that is not.
21. As a player, I want the Dreamweavers distinguishable with colour removed, so that their identity is available to me regardless of how I see.
22. As a player, I want Light to be straight, settled lines and a bright white-to-blue, so that it reads as the one that knows its path.
23. As a player, I want Shadow to be angular and sharp with pulsing yellows and a direction I cannot predict, so that it reads as the one that will not hold still.
24. As a player, I want Ambition to bend and curve in crimson and to bend the visuals around it when it speaks, so that it reads as the one that will not stay inside its frame.
25. As a player, I want a Dreamweaver to ask whether it should keep typing or talk, so that its capability is being negotiated in front of me.
26. As a player, I want its speech to arrive as modem sound rather than words, so that I understand it has a carrier but not yet a language.
27. As a player, I want to choose from three options at each question, so that the exchange stays a conversation I can act in.
28. As a player, I do not want to be told which Dreamweaver an option belongs to, so that the choice stays a judgement rather than a poll.
29. As a player, I want my choice to determine who speaks next, so that the conversation feels steered by me.
30. As a player, I want no Dreamweaver to get more than one turn, so that the scene has an end.
31. As a player, I want my choice to hand over to the next Dreamweaver who has not yet spoken, so that my intent is honoured without stalling the scene.
32. As a player, I want Omega to ask the first and the last question, so that the machine frames the encounter.
33. As a player, I want the last question to be about my own name, so that the machine's curiosity turns on me.
34. As a player, I want Omega to answer my name with something it has lost — *"I had a name once, was that mine?"* — so that the scene's final note is the machine failing to hold itself.
35. As a player, I want the scene to cut immediately after that line, so that the last thing I have is a question.
36. As a player, I want the same choices to lead somewhere different on a second run, so that replaying is rewarded.
37. As a player, I want to be able to see only one path per pass, so that the loop has something left to withhold.
38. As a player who uses reduced motion, I want the journey and the spins replaced by cuts and wipes, so that I can play the same scene without discomfort.
39. As a player who zooms to 200%, I want the text and the choices to remain readable and on-screen, so that the scene does not break.
40. As a player using a keyboard only, I want every choice and the name entry reachable and operable, so that no input method is required beyond the documented controls.
41. As a player, I want the name entry to show me clearly where I am typing without the scene gaining an unwanted border, so that the bare-cursor feeling survives contact with usability.
42. As a returning player, I want the echo count to rise each pass, so that I know the loop is not repeating but deepening.
43. As a player, I never want to be told who or what Omega is, so that the mystery is mine to hold.
44. As a player, I never want to see a face, so that whatever finally has one means something.
45. As a developer, I want the hidden scoring to be pure and testable without a browser, so that the scene's rules can be verified independently of its visuals.
46. As a developer, I want the same seed to produce the same scene, so that evidence and debugging are reproducible.
47. As a developer, I want the scene drivable through real input in a browser, so that screenshots never stand in for proof.
48. As a developer, I want the Dreamweaver wording to live in content, not in the scene, so that copy can be iterated without touching the build.

## Implementation Decisions

**Modules.** Following the ownership boundaries already declared in the design spec: `src/core` (host, fixed-step loop, seeded RNG, input intents, typed events), `src/game` (affinity, turn sequence, ladder, run state), `src/content` (question data and the Dreamweaver creative cards), `src/ui` (the console text engine, choices, name entry), `src/systems` (the cosmic background, the lemniscate path, effects, era/render).

**Two layers, deliberately.** The console's text is a DOM layer; the universe, the lemniscate, the Dreamweaver primitives, and the effects are rendered in the Three.js canvas beneath it. This is chosen so that text stays crisp and genuinely accessible — focus, captions, selection, and 200% zoom all work with real text — while the world keeps real depth. The console "pulling into 3D" is a CSS 3D transform on the text container, not a texture, so the text keeps typing while it moves.

**The background is not built from Omega's code.** It is the layer the machine is running inside. It therefore does not glitch, does not degrade, and does not participate in the ladder. Everything Omega makes is inside it and can fail; the universe behind it cannot. This is the scene's only honest surface.

**Identity lives in behaviour, not shape.** This is forced by the ladder: at the dot rung there are no straight lines and nothing to bend. So each Dreamweaver's identity must be expressible at every rung, which makes motion, timing, and cadence the carrier of identity and shape merely the current body.

**Hidden affinity.** Per the design owner, hidden from the player:

```
affinity = { light: number, shadow: number, ambition: number }

Omega's question      -> the represented Dreamweaver gains 1
Dreamweaver's question-> its own interpretation gains 2 to that Dreamweaver
                         any other Dreamweaver's option gains 1 to that one
```

The final pairing attaches by highest affinity; ties resolve by canonical order (`light`, `shadow`, `ambition`) so the result is never arbitrary; an all-zero result attaches nobody.

**Turn sequence.** Omega asks first. The chosen option names the next Dreamweaver. That Dreamweaver asks, and its chosen option names the next — **unless that Dreamweaver has already spoken**, in which case the turn passes to the next Dreamweaver who has not, in canonical order. When all three have spoken, Omega asks the last question. No Dreamweaver gets more than one turn.

**The ladder.** `dot → line → box → icon`, strictly non-decreasing across the scene, and extensible past `icon` later. A rung becomes available only when the code loop has added that capability, which is what makes the environment read as progressively loading.

**Ghostwriting.** Text is emitted character by character with authored processing pauses and **authored** mistakes that are corrected in place. Mistakes are content, not random noise — the same seed produces the same mistakes.

**Determinism.** One fixed update order and one seeded RNG own every non-authored variation: question draw, Shadow's directional randomness, spark and effect placement. Same seed plus same inputs reproduces the scene exactly.

**Audio hooks.** Two events exist in this spec's scope and no assets: a Dreamweaver asking to speak, and a Dreamweaver speaking in a carrier without a language. Both emit typed events; no voice, whisper, or modem asset is produced here.

**Accessibility from the start.** Reduced motion substitutes cuts and wipes for the journey, the spins, and the FOV movement. Colour is never the only carrier of a Dreamweaver's identity. The name field is focusable and its focus must be visible without introducing the frame the design deliberately removed.

## Testing Decisions

**What makes a good test here.** Only external behaviour. A test may assert what a player or a caller can observe — points awarded, who speaks next, which rung is showing, what the scene does on real input — and must not assert internal structure, module layout, or private state.

**Seam 1 — the pure rules (unit).** The hidden scoring, the turn sequence, and the ladder progression are tested without a browser, without DOM, and without Three.js. This is the highest seam available for the rules and it is the seam the design owner's scoring decision is pinned to. **Prior art:** the RED test already in the tree at `tests/unit/scene-one.test.ts`, which encodes the scoring and turn rules directly and is currently failing because no production module exists.

**Seam 2 — the scene through real input (browser).** The scene is driven to completion through the declared test hooks and real keyboard input, so that no screenshot can stand in for proof. **Prior art:** `tests/browser/boot.spec.ts`, and the acceptance surface already required by the loop contract.

**Seam count.** Two, and both already exist as declared surfaces. No new seam is introduced, and the browser seam is the highest available.

**Additional checks.** Colour-independence (all three Dreamweavers distinguishable with colour removed); determinism (same seed, same question order and same speaker rotation across two runs); reduced-motion (the journey is replaced, not merely slowed); and zoom/reflow at 200%.

## Out of Scope

- Scene 2 and everything after it — the rogue chambers, the town, party recruitment, the fracture routes, the threshold, the bridge, the collapse.
- The final text of the three Dreamweaver questions. Each gets a creative card instead.
- Omega's identity, nature, or reveal. Omega is never named in Scene 1.
- Runtime LLM question generation. The question pool is authored; variation is seeded, not generated.
- Blender or any generated art assets. Alpha 0.1's visuals stay procedural and authored.
- Voice, whisper, or modem audio assets. Only the event hooks are in scope.
- Inventory, loot, skill trees, combat systems, backend services, database persistence, or any API.
- Any face. Deliberately out of scope until the ladder can justify one.

## Further Notes

### Seams — confirm before build

Per the spec skill, these seams should match the owner's expectations before work starts: **two seams — one pure unit seam for the hidden rules, one browser seam through the declared test hooks and real input.** If you would rather the rules be verified only through the browser, the unit seam drops and the rule tests move behind the hooks.

### Creative cards — the Dreamweaver text (to improve, not final)

Each card holds a concept and what to improve. Wording is explicitly provisional.

- **Light — the warner.** Knows the path and says so plainly; the one that tells you not to. *To improve:* find the line that warns without lecturing, in the register of a thing that has watched this fail many times.
- **Shadow — the inviter.** Deals in wishes and takes something in return; the one that makes the offer sound like a favour. *To improve:* make the temptation specific enough to be tempting, and make the cost visible only afterwards.
- **Ambition — the one that asks what it is worth.** Does what is needed regardless; the one that will spend you. *To improve:* land the question of worth without it becoming a riddle with an answer.

All three are aspects of one persona: their combined dialogue should complete a whole, and no single one should read as the complete voice.

### Contradictions still open (recorded, not resolved)

1. **Question count.** "Each Dreamweaver poses 3 questions each" versus "each Dreamweaver asks one question, and Omega gets the first and last." This spec assumes **one each in Scene 1**, building to three each across later loops.
2. **Camera contract.** The design spec fixes the terminal camera to a fixed front plane; the cosmic journey and the spin move it. This spec treats the journey as the reason to amend that contract for Scene 1.
3. **The name the player gave Omega.** An earlier invariant recorded it as permanent across loops. This spec has the *player* named and Omega's own name left open. Recorded as superseding, not assumed.
4. **Shadow's colour.** Described as "yellow of various pulsing shades" here and "gold-amber" in earlier canon. `t1` samples the logo and settles it.

### Why "no face" is a rule

There is no face because Omega cannot make one yet. The absence is an inventory limit, not a style choice — which means a face appearing later is an upgrade rather than a reveal, and should be authored as one.
