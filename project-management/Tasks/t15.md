## The problem in one line

**The design owner's own repository context file names the trio one way, and the Scene 1 spec plus the environment skill name it another. Both are live. An agent loading the wrong one codes the wrong vocabulary into the scene.**

Discovered during the canon sweep recorded in [[t14]]. Raised, not resolved — a contradiction is flagged, never quietly picked.

## Position A — Light · Mischief · Wrath

| Source | What it says |
|---|---|
| **`AGENTS.md`** — the game repo's own agent context file | *"the Dreamweaver reshapes reality through choices across three forces: `Luminary / Trickster / Shadow` in the engine, displayed as `LIGHT / MISCHIEF / WRATH`."* |
| **`SOUL.md`** — `omega-game-director`, and byte-identically in `game-dev` | *"The three public choices are LIGHT, MISCHIEF, and WRATH; internal mappings are LUMINARY, TRICKSTER, and SHADOW."* |
| **This session's director instructions** | Same wording as the soul file |

## Position B — Light · Shadow · Ambition

| Source | What it says |
|---|---|
| **[[t3]]** — the Scene 1 spec, `ready-for-agent` | Light is *"straight, settled lines and a bright white-to-blue"*; Shadow is *"angular and sharp with pulsing yellows"*; Ambition is *"crimson and bends the visuals around it when it speaks"*. The affinity object is `{ light, shadow, ambition }` and ties resolve *"by canonical order (`light`, `shadow`, `ambition`)"* |
| **`omega-spiral-environment` skill** | *"The public trio is **Light**, **Shadow**, **Ambition**; their code ids are `luminary`, `shadow`, `ambition`… The source repo's older `light` / `mischief` / `wrath` naming is **superseded**. Do not introduce `mischief`, `wrath`, or `trickster`."* |
| **[[t4]]** and the landed code | `src/game/affinity.ts` implements `{ light, shadow, ambition }`. 50 tests pass against it |

**Note the double conflict.** It is not only the names — it is the **mapping**. Position A puts `SHADOW` as the *internal* id of the third public force (`WRATH`). Position B puts `shadow` as the **middle** force and `ambition` as the third. The same word occupies a different slot in each canon.

## Why this cannot be left standing

1. **The landed code is already committed to Position B.** `src/game/affinity.ts` and 50 passing unit tests use `light` / `shadow` / `ambition`. If Position A is correct, the foundation is built on the wrong vocabulary and [[t4]] reopens.
2. **The colour canon exists only under Position B.** *Silver-white/blue-white (Light)*, *gold-amber (Shadow)*, *crimson (Ambition)* — sampled from the logo, and asserted as canon. There are **no colours recorded anywhere for Mischief or Wrath.** So Position A currently has no visual identity at all.
3. **[[t3]]'s Dreamweaver characterisation depends on the mapping.** *Light the warner*, *Shadow the inviter who deals in wishes*, *Ambition the one that asks what it is worth*. **Ambition is a character with a voice and a colour, and Mischief/Wrath are not.**
4. **An agent cannot detect this.** An agent loading one source sees a self-consistent vocabulary and proceeds confidently. Nothing in either file admits the other exists.

## The question for the design owner

**Which trio is canonical?**

- **A — Light / Mischief / Wrath** (internal Luminary / Trickster / Shadow), in which case [[t3]], the environment skill, the logo-derived colours, and the landed `affinity` module are all wrong and must be revised.
- **B — Light / Shadow / Ambition** (code ids `light` / `shadow` / `ambition`), in which case `AGENTS.md`, both soul files, and this session's director instructions are wrong and must be revised.
- **C — something else**, in which case please state it, and the colours for any force currently without them.

**A second, smaller question, because it will come up immediately:** `AGENTS.md` describes a character called the **Dreamweaver** as the thing that reshapes reality, while [[t3]] describes **three** Dreamweavers as aspects of one shattered persona. Is "the Dreamweaver" the collective name for all three, or a fourth thing?

## Acceptance

- [ ] The owner states which trio is canonical, or supplies a third.
- [ ] Every source in the losing position is corrected **in its own lane** — creative sources via Obsidian, `AGENTS.md` via a GitHub issue.
- [ ] The colours for every force are recorded, or their absence is recorded as deliberate.
- [ ] The Dreamweaver question is answered.
- [ ] [[t14]] is updated to move the resolved item out of its contradiction section and into its canon section.

## Out of Scope

- **Choosing an answer.** Agents report questions; the owner decides.
- **Editing any file while the question is open.** A wrong "fix" is worse than the contradiction.
- **Reverting [[t4]].** Its implementation follows [[t3]], which is the current authority for Scene 1. It is not at fault.

## Further Notes

**Why this survived so long.** Each source is internally consistent, and no single file contains both positions — so no reader ever sees the conflict. It was only visible by reading `AGENTS.md` and `t3` in the same pass, which is exactly what the canon sweep forced.

**What it tells us about the file habit.** This is the concrete cost of canon living outside the tracker: two vocabularies for the same three characters, one of them with no colours and no voices, both of them loadable by a worker on any given day. **A single `spec` row would have caught it in one read.**
