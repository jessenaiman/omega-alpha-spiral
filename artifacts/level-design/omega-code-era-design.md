# Omega Spiral: code-era construction reference

Status: design proposal for owner review, 2026-09-24. This expands the approved broad progression; it does not claim that the running game already looks this way.

## The rule Omega builds by

Omega gains a way to **make** something at each step: a signal, a cell, a tile, a sprite, a textured plane, a polygon, then a composed world. A later scene retains recognizable traces of earlier work. New effects can illuminate or damage those traces, but cannot turn every object into the same block or make the player, route, question, and exits hard to read. **An era is an applied, configurable rendering component, not the identity of a whole floor.**

The eight-entry [era presentation artifact](<../../project-management/t5 Ghost terminal presentation and copy.md>) is a reference for display hardware, surfaces, cursors, and production prompts. Its entries are **parallel historical methods**, not eight game levels and not the whole art direction. Historical device behavior, creative 3D adaptation, and modern production tools must be identified separately. A Dream Textures prompt or BlenderKit search term describes a possible production step; it is not evidence that an asset or plugin exists in the game.

## Era treatment component

One `EraTreatment` attaches to a renderable target: Omega's terminal surface, a Dreamweaver letter group, a path fragment, a prop, a sky plane, or a town object. A scene may set a default preset; any target may override it. Multiple treatments can coexist in one camera view. An older treatment may remain on a source object while newer work appears beside or over it. The component must not change collision, route topology, dialogue text, or the underlying asset's provenance.

The design-facing controls are **preset**, **target**, **palette**, **pixel/cell scale**, **color quantization**, **dither**, **scanline or beam behavior**, **phosphor/persistence**, **noise/damage**, and **blend strength**. A preset supplies historical starting values, but the designer can tune them for legibility. Cursor shape, line reveal, paper advance, and Dreamweaver writing motion are companion behaviors driven by the same preset; they are not falsely described as fragment-shader operations. This is a proposed component contract, not an implemented API or `.oml` syntax.

Render order: author a clean shape or glyph → apply its local era treatment → composite retained older layers → apply restrained shared damage → add only the instability specific to that target. The player, choice route, and active words are readability masks: their contrast and silhouette survive the strongest effect settings. Floor 7's recycled town applies different era components **per sourced object**, which is how incompatible aspect and pixel densities can coexist without changing the gameplay camera.

The dialogue studio needs a design panel for selecting a target and tuning this treatment while previewing the authored `.oml` line and `.omd` persona. A single global “Shared text era” dropdown is an incomplete control surface. The game reads the saved custom text/configuration files directly; the studio does not send commands into a running scene.

**Existing seam:** [GhostLetters](../../src/intro/ghost-type-study/GhostLetters.ts) already uses a Three.js `ShaderMaterial` with configurable scan, dot, halo, and cell uniforms and swaps a generated glyph atlas when its tradition changes. That is a lettering-specific prototype of the component. It does not yet expose target selection, palette quantization, dither, damage, or blending for other world materials. Preserve its working text path while broadening the design; do not claim this document itself installs a general shader.

## Eight source methods as reusable treatments

These are **candidate first placements**, not one mandatory effect per level. Each can return on an inherited object after a later capability appears. The original IDs are retained so a future preset mapping can be traced back to the supplied artifact.

| Source method      | Candidate first target                                                                 | Configurable visual behavior                                                        | Later reuse                                                            |
| ------------------ | -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `vector-stroke`    | Opening celestial marks and incomplete path edges                                      | Beam width, stroke order, decay, redraw strength                                    | Underlying construction seams in all later stages                      |
| `teletype-paper`   | An archival strip beside Omega's recorded signal, never Omega's centered screen cursor | Ink variation, paper warmth, carriage delay, strip curl                             | Found messages in the Moving Archive and town                          |
| `block-green-3270` | Protected archive fields or a vault terminal                                           | Field grid, protected/editable contrast, block-update interval                      | Recycled administrative surfaces in the town                           |
| `micro-rom-pixel`  | Forming hero cells and the first repeated route tiles                                  | Cell size, limited palette, pixel snap, composite softness                          | Sprite and tile ancestry through Floors 1–5                            |
| `vt100-phosphor`   | Omega's centered terminal in an Opening passage                                        | Character grid, phosphor hue, cursor, persistence, scan strength                    | Local ghostwriting and terminal restarts in the town                   |
| `dos-vga-console`  | A later Opening threshold surface or a Floor 4 control surface                         | Character-cell size, 16-color text attributes, box drawing, mode-switch flicker     | Older screens found within Floor 7's mixed town                        |
| `os2-workplace`    | A later archive or town object plane                                                   | Bevel, folder/object spacing, window repaint; choose 1988 PM or 1992 WPS explicitly | Misplaced desktop windows in the town, only after their source appears |
| `truetype-desktop` | A late-stage authored interface or an object in the town                               | Outline hinting, scale, grayscale smoothing when appropriate, gray chrome           | A clean modern layer under the finale's richer effects                 |

The source's `pluginPrompts` can inform a texture or prop study for each row. A generated texture must be fitted to the target's actual geometry and shader settings; the prompt alone does not complete the design.

## Scene and persona design contract

- The game reads authored `.oml` scene text and `.omd` persona definitions. The studio edits and previews those files; it does not need a special live connection to the game.
- A scene supplies a default era-treatment preset; a target can override and blend it. Light, Shadow, and Ambition keep their identity color, cadence, correction behavior, and spatial grammar across scene changes. Omega remains a centered terminal/cursor presence.
- Build each line cleanly in its chosen method, retain useful prior layers, then apply one restrained corruption pass. Damage is an effect on authored work, not the letter design itself.
- The [UI designer's pattern guide](../../.agents/skills/threejs-game-ui-designer/references/ui-patterns.md) sets the hierarchy: status, objective, immediate choice feedback, then flavor. Keep choice words and signs outside the hero's route; check text fit at actual play size before scoring a scene.
- A capability is approved for a floor only after a source piece, its in-game reuse, and a running frame show the same design intent. Concept art, source code, or a bot route alone cannot approve its look.
